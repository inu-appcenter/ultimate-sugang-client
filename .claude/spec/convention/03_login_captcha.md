# convention 03 — 로그인 · CAPTCHA

> 권위: `spec/05_screens_spec.md` §2·§10 · `spec/01_behavior_spec.md` 부록 A · **D54**(5차 실측 대조, 상위 권위) · D55(인증 도입).

## §1 로그인 화면 (`features/login/*` · `app/main.tsx`)

### 1.1 마크업·문구
- 원본 마크업·클래스 그대로: `#login .tit / .login_con / .login_area / .id_w / .btn_login / .btn_etc*`.
- **제목은 원본 문구를 그대로 복원**한다(D54 D5-01, D12 의 `[LOGO]`·`APP_TITLE` 대체):
  `인천대학교`(48px bold · 순수 검정 `--black`) + 공백 + `대학 수강신청`(48px bold `--login-title`) + `<br>`
  + `Undergraduate Course Registration`(h1 자체 24px bold). `LOGIN` 은 `h3 > span` 48px 흰색.
  → **학교 이미지 애셋은 여전히 쓰지 않는다**(원§0). 전부 텍스트다.
- 안내 문구는 파란 박스 **아래로 넘쳐 흐른다**(원본 동일). 1행 `※ 수강신청 URL …`(em_blue, `<a>` 안) ·
  3행 `※ 호환성 문제에 따라 …`(em_red). **원본 2행(모의 수강신청 INTIP)은 삭제**한다(D54 D5-05).
- `찾기` 링크·바로가기 4종은 **`href` 없이 렌더만** 한다(D19).
- `#login` 중앙 정렬은 원문 그대로 `margin:-190px 0 0 -464px; height:380px`(D54 D5-04).
  배너가 사라졌으므로 D36 의 transform 보정은 폐기했다.
- 입력 필드에 배경색을 주지 않는다(D54 D5-03) — 원본 CSS 에 지정이 없고, 실측된 `#E8F0FE` 는 Chrome 자동완성 하이라이트였다.
- 전역 `a:hover { color: var(--login-hint) }`(D54 D5-06) — 원본이 전역으로 거는 규칙이라
  **수강신청 화면 메뉴 탭까지** hover 시 글자색이 옅어진다. 버튼별 hover 규칙을 새로 만들지 않는다.
  자식이 자기 색을 직접 지정한 경우(안내 문구 `span.em_blue`)는 상속이 아니라 자기 선언이 이겨 파랑을 유지한다.

### 1.2 비밀번호 필드
- **비밀번호 입력 행은 로그인 화면에만 존재한다.** 그 외 화면에는 여전히 없다(스모크가 단언).
- D54 D5-02 에서 "시각 재현 전용"으로 되살렸다가 **D55 로 개정** — 서버가 JWT 를 유지하므로
  RHF 에 등록하고 실제로 전송한다. 행을 빼면 `.btn_login` 72px · `.id_w` 143px 근거가 무너지기도 한다.
- mock 어댑터에는 인증이 없어 비밀번호를 보지 않는다 — 학번만으로 진입한다(로컬 연습·스모크 유지).
  그래서 비밀번호 필수 검증은 `VITE_API_ADAPTER=http` 일 때만 건다.
- ⚠️ 하네스는 이 변경(실제 포털과 같은 모습으로 비밀번호를 받는 화면)에 반대 의견을 냈고, 사용자가 재확인해 진행했다.

### 1.3 동작
- 빈 값이면 **진입하지 않고 메시지도 없다**(D19) — 검증 실패 시 `onInvalid` 를 주지 않는 방식.
- 로그인 실패 alert 문구는 원본 실패 화면이 미확인이라 카탈로그와 같은 포맷으로 하네스가 작성했다(D55):
  `학번 또는 비밀번호가 올바르지 않습니다.\n Invalid ID or password.` (서버 `MEM-001`·`MEM-002` 대응)
- **`<form>` 을 쓰지 않는다** — 원 CSS 가 `.id_w > p` · `.login_area > div` 직계 선택자라 래퍼를 끼우면 레이아웃이 깨진다.
  Enter 는 각 input 에서 처리한다.
- ⚠️ 서버 v1 은 로그인 본문이 `{ email, password }` 다. 프론트는 확정된 목표 계약 `{ studentId, password }` 로 보내며
  서버 변경을 요청해 둔 상태다.

### 1.4 스타일시트 로드 순서 (`app/main.tsx`)
- `jquery-confirm` 은 **CSS 만** import 한다. 모달 DOM·상태는 React 가 소유하므로 jQuery 런타임은 번들에 들어가지 않는다
  (`jquery` 는 `jquery-confirm` 의 의존성으로 설치만 됨).
- **`jquery-confirm` CSS 가 `globals.css` 보다 먼저 와야 한다** — 하네스 리셋/토큰 오버라이드가 뒤에서 이겨야 하기 때문.
  import 순서를 바꾸면 CAPTCHA 모달과 전역 스타일이 어긋난다.

## §2 CAPTCHA (`features/sukang/captcha/*`)

- `VITE_CAPTCHA=off` 가 기본이다(D34). 사용자 대면 토글 UI 는 없다.
- 게이트는 신청 실행을 감싸는 `beforeSubmit` 형태다: off 면 즉시 실행, on 이면 모달 →
  정답이면 **보류했던 요청을 자동 수행**, 오답이면 모달 유지 + 에러 + 이미지 재생성 + Remain 1 차감. `닫기` = 보류 요청 폐기.
- **오답 1회당 Remain 은 정확히 1 감소**한다(D54 — 명세의 `10 → 8` 관측은 오기로 확정).
  누적 10회 도달 시 자동 로그아웃(`/` 복귀). 카운터는 세션 유지이며 정답을 맞혀도 초기화하지 않는다.
- 모달은 원본과 같은 **jquery-confirm(`jconfirm-light`) DOM 구조**를 그대로 쓴다. 벤더 CSS 가 박스(730×374)·제목·버튼 영역을
  만들고, `.capt_*` 는 학교가 넣은 본문 마크업이다. 벤더 기본값 중 2가지만 덧쓴다(둘 다 폰트 폴백에서만 어긋난다):
  `.jconfirm-title-c { height:35px }` · `.jconfirm-content-pane { display:block }`.
- 뒤 클릭·ESC 로 닫지 않는다(보수적 선택). Enter = 확인.
- 입력창은 `size="20"` `maxlength="4"` 이고 **폭·높이를 고정하지 않는다**(D53 D4-03 준용 — 원본과 같은 규칙이어야
  환경이 달라져도 함께 움직인다). `확인(Confirm)` 버튼은 `.btn_mrc` 재사용.
- 본문 강조: `"확인"` 은 `--em-blue`, 횟수 숫자(`10`·Remain)는 `--em-red`. 명세가 구간을 특정하지 않아
  **모든 횟수 숫자**에 적용한 판단이다(되돌리려면 `captcha/texts.ts` 세그먼트만 고치면 된다).
- 본문 오탈자 `잘 못` 은 **원문 유지**(D5).
- 이미지는 원본이 서버(`macroStream.jsp`)에서 내려주지만 모의 사이트는 `<canvas>` 로 직접 그린다(의존성 없음):
  210×210 · 숫자 1000~9999(선두 0 없음) · 노이즈 베지어 곡선 · 배경 4색 로테이션.
  **색은 CSS 토큰을 `getComputedStyle` 로 읽는다 — raw 값 금지.**
  노이즈 밀도·글자 크기·회전 폭은 원본 스크린샷 기반 근사값이다(미확인 항목).
- 정답이 바뀌면 부모가 `key` 로 모달을 리마운트해 입력값을 초기화한다.
