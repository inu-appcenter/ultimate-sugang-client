# convention 02 — 화면 구조·시각 재현

> 권위: `spec/05_screens_spec.md`(화면 시각) · `spec/04_design_system.md`(토큰) · `.claude/rules/ui-conventions.md`.
> **단, 실측 대조 결정(D50·D51·D52·D53)이 SoT 문서보다 우선**한다 — 아래 서술은 실측값 기준이다.
> 전제: 원본 CSS 이식 프로젝트(D2) — shadcn/ui·토스트 미도입, 원본 클래스명 사용, 다이얼로그는 네이티브 alert/confirm.

## §1 전역 골격 (`components/SukangShell.tsx` · `app/*`)

단일 `.wrap`(80% · min-width 1400px, D7·D8) 안에 위 → 아래:

```
table.perT  →  div.btn_area(탭 7 + 주의 문구 인라인)  →  div.sjt_sch(제목·검색행)
   →  [조회 전 div.guide_box  |  조회 후 div.sch_areaT + table.dataT]  →  div.regi_area(신청내역)
```

- `?menu` 가 없거나 무효면 **랜딩 상태**(D35) — 제목·결과 영역 없이 전공과목 안내만 + 신청내역.
- 탭 전환 시 화면 컴포넌트를 `key` 로 교체한다(이전 결과 미유지, 05 §3-5).
- **연습용 배너는 제거됐다**(D52 D3-02, D11 폐기) — 원본과 세로 좌표를 맞추기 위함. `<title>` 은 `인천대학교 모의 수강신청`.
- iframe 미재현, 단일 SPA. 라우트는 `/`(로그인) · `/sukang?menu={Key}`(D7).

## §2 상단 학적 정보 (`components/PerTable.tsx`)

- `table.perT` — th/td 7개 교차, `.titY` 만 `scope="col"`. 포맷 `{학번} / {성명}`, `{학년} / {학적상태}`(공백 포함 슬래시).
- **`<colgroup>` 7개(22/12/14/12/14/12/14%)가 반드시 있어야 한다**(D50 D-03). 원본 마크업에는 있는데 명세 원§5.2 에서 누락됐다.
  `table-layout:fixed` 라 없으면 7등분되어 `.titY` 영문이 3줄로 접힌다. 값은 `columns.ts` 의 `PER_TABLE_COL_WIDTHS`.
- Student 로딩 중에는 값 셀이 빈 문자열, 에러는 alert 1회 + 빈 셀(D9 준용).

## §3 메뉴 탭·주의 문구 (`components/MenuTabs.tsx` · `constants/screens.ts`)

- 탭 7개는 `a.btn_re`(한글 `<br>` 영문). 영문은 `span.tab-en` = 10px `--blue-en` — 헤더 `.th-en` 과 같은 값(D51 D2-02).
- **활성 탭 강조는 없다**(D17 — 원본 CSS 에 활성 규칙 자체가 없다). 클릭은 `?menu=` 쿼리 전환.
- 주의 문구 `.noti` 는 **우측 끝 정렬이 아니라 마지막 탭 바로 뒤 인라인**이다(D52 D3-08, 간격 4.3px).
  → `.btn_area` 에 flex/justify-between 을 쓰면 안 된다. 원 CSS 그대로의 블록 + 인라인 흐름이라야
  탭 높이가 원본과 같은 37px 이 된다(flex 컨테이너였을 때 38.5px).
- 문구는 평문이 아니라 구간 마크업이다(D51 D2-03): `<em>고동색→야간학과</em>`(maroon) / `<span>회색→마감강좌</span>`(muted).
- 탭 간격 `margin-right:4.3px`(D52 D3-01) — 원본은 `1px` + HTML 소스의 공백 텍스트 노드(≈3.3px)인데
  JSX 는 그 공백을 없애므로 CSS 로 직접 준다. `{' '}` 로 넣으면 폰트 폴백에 따라 폭이 흔들린다.
- 화면 제목(`>> 화면명`)은 탭 이름과 미묘하게 다르다 — `SCREENS[key].title` 원문을 쓴다(01 §2-3).

## §4 제목 라인·검색행 (`components/ScreenTitle.tsx` · `SearchSpacer` · `SearchSelect` · `SearchLinkedSelect` · `SearchText`)

- 구조: `>> 제목`(`td.tit_scr`) → `→` → 조건 → `button.btn_search`. 조건 없는 화면은 제목만(구분선 없음).
- **검색행은 `<table>` 이고 요소 사이 간격은 `<td width="10px">` 스페이서 셀이 만든다**(D52 D3-03).
  margin/padding 이 아니다. 원본 좌표: 제목 30 → select 116.8 → [조회] 260.8. 좌측 들여쓰기 20px · 행 높이 25px.
- 이 `<table>` 은 원§8.4 인라인 style(`font-weight:bold; font-size:9pt; font-family:굴림; text-align:center`)을 그대로 갖는다.
  **`font-family:굴림`(폴백 스택 없음)이 폭의 원인**이다 — 제목 56.4 / `→` 10.4. body 스택으로 렌더하면
  `arial` 이 U+2192 를 12px 로 그려 어긋난다.
- 검색행에는 **하단 여백도 구분선도 없다**(D52 D3-05·D3-06). 안내 박스는 검색행 바로 아래에 붙고,
  시각적 간격은 안내 박스의 `margin-top:5px` 가 담당한다.
- **화면 제목은 평문이 아니다**(D50 D-05): bold · `--slate-title` · 12px · center(`.tit_scr`).
  조건이 있는 화면에서는 `<table>` 전체가 아니라 **제목 `<td>` 에만** 걸어야 검색 조건이 물들지 않는다.
- **조회 버튼**: `.btn_sch`(진회색+흰글씨)는 원본 CSS 에 존재하지만 **조회 버튼에는 적용되지 않는 규칙**이다(D51 D2-04).
  실측은 125×22 양각 버튼(`--btn-sch-bg` 배경 · `--slate-title` 글자 · 상좌 밝은/우하 어두운 테두리) → 전용 클래스 `.btn_search`.
- **폼 컨트롤은 UA 기본 스타일 그대로 둔다**(D51 D2-08 · D53 D4-03). 원본 5개 화면에는 `.sjt_sch` 규칙 자체가 없어
  원§6 의 200×32 규칙은 적용 대상이 아니다. 텍스트 입력은 `size="30"` + `box-sizing:content-box` + `width/height:auto`
  로 두어 브라우저가 폭·높이를 정하게 한다(실측 185×20.5) — 고정 px 을 주면 원본과 함께 움직이지 않는다.
- `select` 에만 `text-align:center` 를 명시한다(D52 D3-07) — 원본은 검색행 테이블에서 상속받은 값인데
  Chrome UA 가 select 의 text-align 을 자체 값으로 덮기 때문이다.
- **교양 2단 연동 select**(05 §5-1, 원§4.1): `#cmbCptnGbn` + `#cmbFldGnb11/21/23` **3개를 모두 DOM 에 렌더**하고
  표시만 토글한다. 1단이 11/21/23 이면 대응 하위 1개만 표시, 50/70/80/미선택이면 전부 숨김.
  1단을 바꾸면 하위 선택을 초기화한다. 하위가 전부 숨겨지면 두 번째 `→` 와 앞뒤 스페이서까지 함께 접는다.
- 단일 select(TAGWA·YUNGAE)는 placeholder(value 빈 문자열) + 원문 순서 옵션. 코드 미제공이라 이름이 곧 값(D30).

## §5 조회 전 안내 박스 (`components/GuideBox.tsx` · `constants/notices.ts` · `screens/LandingScreen.tsx`)

- **원본은 조회 전에 `.sch_areaT` 도 결과 `table.dataT` 도 렌더하지 않는다**(D51 D2-01, 실측 0개).
  그 자리에 안내 박스가 있고 조회 후 결과 영역으로 **교체**된다 → 화면별 안내 문구는 **박스 안에만** 존재하고
  조회 후에는 사라진다.
- 파생: 조건 없는 화면(장바구니·전공과목·HUSS)은 즉시 로드라 조회 전 상태가 없다 →
  **전공과목 안내는 랜딩 화면에서만 보인다**(D35).
- 박스 치수: 자체 340px + `margin-top:5px`(테두리 바깥) = 점유 345px, 테두리 안쪽 여백은 4방향 3px(D52 D3-04).
- 본문은 `<p>` 가 아니라 `<br>` 로 줄을 나누는 원본 구조 — 선두 빈 줄 → `*` 머리줄 → 빈 줄 → 항목들.
- 안내 문구 좌측 들여쓰기는 원본이 각 줄 앞의 THIN SPACE(U+2009)로 만든다(하늘색 영역 좌측에서 20.66px).
  실폭이 폰트 폴백에 좌우되므로 **마크업이 아니라 CSS 로** 재현한다(`.guide_inner { padding-left: 20.66px }`, D53 D4-01).
- 강조 줄은 원 `<font color>` 그대로 **순수 blue `#0000FF` / red `#FF0000`**(`--em-blue` · `--em-red`)이다 — `--maroon` 이 아니다.
- 불릿 문자는 **`▒`(U+2592)**, `▤` 가 아니다(D53 D4-02). 문구의 띄어쓰기·오탈자는 원문 유지(D5).
- 안내 박스 서체는 원본이 `굴림` 단독 인라인 지정인데 **구현물은 전역 스택 상속으로 두기로 결정**했다(D53 §6.1).
  줄 높이 −1.0px · 1행 글자 폭 +1.6% 편차가 남는 것을 알고 있는 상태이고, 검증에서 실패로 보지 않는다.

## §6 결과 영역·테이블 (`components/CourseTable.tsx` · `CourseTitleCell` · `ActionButton` · `ResultArea` · `CourseScreen`)

- 결과 영역 `.sch_areaT` 는 높이 337px 내부 스크롤 · `box-sizing: content-box` 명시(D40).
  페이지네이션은 없다 — 전건 반환·전건 렌더링.
- `table.dataT` 는 `colgroup` + `thead`(한글 `<br>` 영문) + 4상태(§9). **Data 상태에서만 행을 렌더**한다.
  조회 목록과 신청내역이 같은 컴포넌트를 쓴다.
- `<col>` 은 원본과 같이 **`width` 속성**으로 준다(D51 D2-07). `width=""` 는 잔여폭 흡수이고,
  `table-layout:fixed` 라 px 지정과 표현식이 동일하다.
- 행 색: **마감(grey)이 야간(brown)보다 우선**(05 §4-4). 첫 셀 `.first`, 액션 셀 `.last`.
- 행 hover 배경은 `#E1F1FF`(`--row-hover`, D52 D3-09). 원본은 CSS `:hover` 가 아니라 행마다
  `onmouseover=listColorOn(this)` 인라인 핸들러로 칠하며 **마감 행도 예외가 아니다**.
  셀렉터는 `.sch_areaT table.dataT tbody tr:hover` 로 좁힌다(신청내역 표는 원본 관측 대상이 아니었다).
- 교과목명 셀(원§5.5): `<b>한글명[<span class="tag"> [태그]</span>]</b> <br>(영문명)`.
  태그는 굵은 한글명 **내부**, 앞 공백 1칸. 마감 행에서는 `.dataT .grey .tag { color: inherit }` 로 부모색을 상속한다.
- 액션 셀 3종(05 §4-7): `신청`(btn_blue) · `마감`(btn_grey2) · `취소`(btn_red).
  **`마감` 은 핸들러도 커서도 없다** — 정원 초과는 프론트에서 사전 차단하는 방식이라 클릭 경로 자체가 없다(01 §6-3).
  `action: 'enroll'` 이라도 `course.isClosed` 면 `마감` 으로 렌더한다.
- 원본 마크업이 버튼을 `<a>` 로 쓰므로(`btn_blue`·`btn_re`·`btn_login`…) `role="button"` + `tabIndex={0}` +
  키보드 활성화 핸들러를 직접 붙인다(`shared/lib/keyboard.ts`, D2).
- 표의 `aria-label` 은 원 `summary` 속성 대체다(03 §5-9).

## §7 컬럼 폭·라벨 (`columns.ts`)

- **컬럼 폭은 디자인 토큰이 아니라 화면 설정 데이터**다(D10, 원§3). `<colgroup>` 에 px 로 적용한다.
- 전체 **1378px**(전공과목 기준). 동일 컬럼은 화면이 달라도 같은 폭이고, **교과목명 = 1378 − 나머지 합**이다(05 §4-5).
  → 컬럼 하나의 폭을 바꾸거나 컬럼을 빼면 **교과목명 폭이 따라 움직여 전 컬럼이 밀린다.**
- 명세 밖 폭은 init 도출: 이수영역 125 · 순번 50(실측 35) · 재수강 구분 80(실측 100) · 취소 65.
  `순번 35` · `재수강 구분 100` 은 D51 D2-07 실측값이다.
- 라벨은 01 §5 매트릭스. **영문이 없는 컬럼(요일 및 교시(강의실), 액션)은 한글만** 쓴다(D21).
- **`professor`(교강사) 컬럼은 서버가 항상 빈 문자열을 준다**(D55-9 — 연계 API 원천에 교강사가 없고, 다른 원천을 찾지 않기로 확정).
  그래도 **폭 80px 과 컬럼 자체를 유지**한다: `table-layout:fixed` + `<colgroup>` 이라 내용과 무관하게 고정이고,
  빼면 위 폭 합 규칙이 어긋난다. 스모크 테스트가 이 폭을 단언한다.
- **신청내역 표는 조회 결과 표와 헤더·폭이 일부 다르다**(D51 D2-06·D2-07, 실측):
  요일 및 교시에 영문 `Time Table(Lecture room)` · 개설학과 → `개설학과(부)` · 취소에 `Cancel`.
  교과목명 `<col>` 은 **폭 미지정(가변)** — 고정폭으로 두면 `.wrap` 폭이 바뀔 때 합이 어긋난다.
  조회 결과 표는 조회 전에 렌더되지 않아 실측 대상이 아니었으므로 **기존 라벨을 유지한다(추정 금지).**
- `PER_TABLE_COL_WIDTHS` 는 `table.perT` 용 % 폭이다(§2 참조).

## §8 신청내역 영역 (`components/EnrollmentArea.tsx` · `EnrollmentTable` · `PrintButtons`)

- 구조: `div.regi_area` > 제목 `div.tit_sub`(안에 우측 float 출력 버튼) > `div.leftT` > 신청내역 테이블.
- 제목은 `p.noti_blue`(11px 단색)가 **아니라** `div.tit_sub` 다(D51 D2-05) — 한글 14px/700, 영문 `span.tit-en` 13px/700
  `--blue-en`, 괄호 안내 14px/400, `padding-left:35px`, `margin:30px 0 15px`, 파란 화살표 불릿(자체 제작 12×12 SVG data URI —
  학교 애셋 미사용).
- 제목 오탈자 `registrered` 는 **원문 유지**(D5).
- **출력 버튼은 별도 행(`.regi_top`)이 아니라 `.tit_sub` 안의 `div.tit_btns{float:right}`** 다(D52 D3-11).
  float 는 부모 높이에 기여하지 않아 `.tit_sub` 가 16.5px 한 줄을 유지하고, 제목 하단 → 테이블 상단이 16px 이 된다.
  → **`.tit_sub` 에 clearfix 를 걸면 안 된다.** clearfix 는 `.regi_area` 자신에만 건다.
- 테이블은 `div.leftT`(320px 내부 스크롤 · 테두리 1/1/2px · content-box)로 감싼다(D52 D3-10).
- 출력 버튼 2종은 **화면을 만들지 않고 버튼 + alert 만**이다(D23). 시각은 원본 그대로 유지하고
  **비활성 회색 처리를 하지 않는다.** 클릭 → `연습 사이트에서는 지원하지 않습니다.`
- 취소 플로우(01 §6-2): confirm → cancel → alert → 신청내역 재조회로 행 제거·순번 재부여.
  confirm 을 취소하면 무동작. **조회 목록은 갱신하지 않는다**(D33). 같은 행 진행 중 재클릭은 무시.
- 순번은 1부터, `createdAt` 오름차순.

## §9 4상태·에러·다이얼로그 (`tableStatus.ts` · `useErrorAlert.ts` · `useEnrollFlow.tsx` · `errors.ts` · `shared/lib/*`)

- **4상태는 원본 시각을 유지하는 방식으로 구현한다**(D9):
  Loading = thead 만 + `aria-busy` + [조회] disabled(시각 변화 없음) · Error = alert 1회 + thead 만 ·
  Empty = thead 만(**안내 문구 없음** — 원본 결함 재현, D4) · Data = 행.
  진행 중 재클릭은 로직 가드만 두고 disabled 스타일은 주지 않는다.
- Loading 판정은 **데이터가 없고 조회 중일 때만**이다(D45) — 재조회 중에는 기존 행을 유지한다.
- 같은 error 로 다시 렌더돼도 재알림하지 않는다(리렌더마다 alert 방지). alert 는 React 밖 API 라 Effect 로 동기화한다.
- `SESSION_EXPIRED` 는 alert 후 logout → `RequireSession` 이 `/` 로 보낸다(D14·D32).
- **다이얼로그는 네이티브 `alert`/`confirm` 뿐**이다(D2 — 토스트·커스텀 모달 금지). 유일한 예외가 CAPTCHA 모달(D34).
  `shared/lib/dialog.ts` 는 테스트에서 대체할 수 있게 둔 얇은 래퍼다.
- 신청 플로우(01 §6-1): [신청] → CAPTCHA 게이트 → 서버 검증 → 성공 alert(교과목명 치환) + 신청내역 재조회 /
  실패는 코드별 alert. **조회 목록은 갱신하지 않는다**(D4·D33). 진행 중 재클릭 무시.
