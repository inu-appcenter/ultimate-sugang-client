## §1. 제품 개요·제작 원칙 (원§0, 원§1)

- **목적**: 수강신청 **연습용 모의 사이트**. 구조 = **UI/UX 재현 + 자체 백엔드**. 원본 서버에는 접근하지 않는다. 서버·API 는 별도 존재(계약은 `02` — 미제공 상태, Q-1).
- **재현 대상 / 재현하지 않을 것**

| 재현 대상 | 재현하지 않을 것 |
|---|---|
| DOM 구조, 레이아웃, 클릭 타겟 좌표·크기 | 실제 API 엔드포인트 |
| CSS (색상·폰트·간격·버튼 상태) | 인증/세션 로직 |
| 화면 전환 순서, 안내 문구, 에러 메시지 | 매크로 탐지(`macroChk`) 로직 |
| 검증 규칙의 **동작** | NetFunnel 대기열 연동 |

- **필수 준수 사항 4** (위반 금지)
  1. **비밀번호 필드를 만들지 않는다.** `input[type="password"]` 금지. 학번만 입력받거나 "아무 값이나 입력" 안내로 대체.
  2. **학교 CI/로고는 플레이스홀더로 교체.**
  3. **연습용 배너를 고정 노출.** 문구: `⚠️ 비공식 연습용 사이트 — 실제 수강신청과 무관합니다`
  4. **공개 배포 시 URL 에 `mock`/`practice` 명시**(배포는 사람 몫 — 하네스는 코드만).
- 브라우저 제약(원본): Chrome / Edge 전용, Safari 미지원(원§1).
- 페이징 **없음** — 전건 렌더링 + `overflow-y: auto`(원§1).
- 원본은 `/` 셸 + `<iframe id="sukang">` 구조이나 **모의 사이트는 단일 페이지로 만들어도 된다**(원§1 주석) → D7.

## §3. 도메인 데이터 사전

### §3-1. 엔티티 최소 스키마 (원§12)
```
Course     { id, code, name, nameEn, professor, credits, capacity,
             enrolled, courseType, courseArea, department, grade,
             schedule, tags[], isEnglish, isNight, isClosed }      ← 개정 D26·D27: schedule 은 원문 문자열, isEnglish 추가
Enrollment { studentId, courseId, resolvedType, reAttendance, createdAt }
Student    { id, name, department, grade, status, gpa, creditLimit } ← 개정 D26: gpa(비노출) → 상한 산출
```
> 시드 문서(`intake/INU-시드데이터.md` §0) 필드명 대응: `nameKo`→`name`, `credit`→`credits`. 값·오탈자·끝공백은 시드 원문 그대로(D26).
필드 ↔ 화면 컬럼 대응(§5 매트릭스 기준):

| 필드 | 컬럼 | 비고 |
|---|---|---|

| `Course.courseType` | 이수구분 Course Type(조회 화면) | **개설학과 기준** 값. 관측: `전공심화` |

### §3-2. 이수구분은 파생값이다 (원§10.2) — 중요
이수구분은 강좌의 고정 속성이 아니라 **`(학생 소속 × 강좌 개설학과)`** 로 산출된다.

| | 조회 화면 | 신청내역 |
|---|---|---|
| 경영프로그래밍2 (0012410001) | **전공심화** | **일반선택** |

컴퓨터공학부 학생이 경영학부 과목을 신청하니 값이 바뀌었다.
```
Course.courseType         ← 개설학과 기준 (조회 화면용)
Enrollment.resolvedType   ← 학생 기준 재계산 (신청내역용)
```
이 구분을 놓치면 신청 후 표시가 실제와 달라진다. (산출 규칙 자체는 백엔드 몫 — 프론트는 두 값을 각각 표시만 한다.)

### §3-3. 교과목명 구조 (원§5.5)
- 한글명은 항상 굵게(`<b>`).
- 태그는 **굵은 한글명 내부에** 파란색(`blue`)으로 중첩, 앞에 **공백 1칸**. 종류: `[75분수업]`, `[온라인혼합형강좌]`, `[e-Learning]` + HUSS 변형 `[e-Learning(HUSS)]`, `[온라인혼합형강좌(HUSS)]`(시드 §6, D26). 영문명은 데이터에 괄호가 없고 표시 시 `( )` 로 감싼다.
- 굵은 한글명 뒤 **공백 1칸** → 줄바꿈 → 영문명(괄호 포함, 굵지 않음).
- 마감 행에서는 부모 색(`#848484`)이 상속되어 태그도 회색으로 보인다.
- 예: `현장교육.실습(Ⅴ-1)` / `(INTERNSHIP(Ⅴ-1))` · `대학수학(2) [75분수업]` / `(CALCULUS(2))`

### §3-4. 시간표 문법 (원§11)
```
화 5B-6 (14-202) 수 7-8A (14-202)
│  │      │
│  │      └ 강의실 (건물-호실). 07-505 = 7호관 505호
│  └ 교시
└ 요일
```
| 형식 | 예 | 의미 |
|---|---|---|
| 단순 연속 | `1 2 3` | 1,2,3교시 |
| 범위 + 접미 | `5B-6`, `7-8A` | 75분수업 블록 |
| 범위 | `1-2A`, `2B-3` | |

- 복수 시간대는 **공백으로 이어붙임**. 온라인 강좌는 **빈 문자열**.
- 인턴십 등은 `월 1 2 3 4 5 6 7 8 9 (ZZ-102)` × 5일 형태(`ZZ` = 가상 건물).
- 화면에서는 `text-overflow: ellipsis` 로 잘려 보임(`05`).
- 프론트는 **문자열을 그대로 표시**한다(파싱 필요 없음; 시간 중복 검사는 서버 검증 §6-4).

### §3-5. 행 색상 의미 (원§5.7, 원§8.3 주의 문구)
| 클래스 | 색 | 의미 |
|---|---|---|
| (기본) | 검정 `#333` | 주간학과 수업 |
| `brown` | `maroon` | 야간학과(`isNight`) |
| `grey` | `#848484` | 마감강좌(`isClosed`) |
| `blue` | `#0082A7` | **용도 미확인**(원문) — 트리거 조건 없음 → 사용하지 않음 |

주의 문구 원문: `※ 주의(전공) : 검정색→주간학과 수업 / 고동색→야간학과 / 회색→마감강좌`

### §3-6. 표시 포맷 (원§5.2, 원§10.3)
- 학번/성명: `{학번} / {성명}` · 학년/학적상태: `{학년} / {학적상태}` — **공백 포함 슬래시**. 예 `2022XXXXX / 홍○○`, `4 / 유예`.
- 학기 타이틀: `2026년도 2학기 수강신청` / `2026 Fall course registration` (줄바꿈 병기).
- 신청내역 순번(No): **1부터** 부여, 즉시 행 추가.
- 재수강 구분: 신규 신청 시 **빈 값**.
- 원어여부: `isEnglish` 면 `EN(원어)`, 아니면 빈 셀(D27).

### §3-7. 코드 체계 (권위 = `02 §5`)
- 교양 이수구분 6 → 하위 이수영역(기초 2 / 핵심 6 / 심화 5). **3단계 이상은 존재하지 않는다**(검증 완료).

## §4. 검색·조회 동작 (화면별)

### §4-1. 공통
- 조회 트리거: 조건 없는 화면은 **탭 진입 시 즉시 로드**, 조건 있는 화면은 **[조회 (Search)] 클릭**.
- 결과는 페이징 없이 **전건 렌더링**(원§1). 결과 영역은 고정 높이 스크롤(`05`).
- **결과 0건**: 헤더만 렌더링, tbody 비움, **"결과 없음" 안내 문구 없음**(원§10.3) → D4 / Q-3.
- 결과 컬럼 세트는 화면별 설정값으로 주입(원§3 구현 권장). 컬럼 매트릭스 = §5.
- 조회 결과의 각 행 액션: `신청`(btn_blue) 또는 `마감`(btn_grey2, 클릭 불가 §6-3).
> 🙋🏻 **Q-7** 검색 조건 미충족 상태에서 [조회] 를 눌렀을 때의 동작(메시지·무시 여부)이 명세에 없음(기본값: 요청 안 보냄, 메시지 없음).

### §4-2. `BASKET` 장바구니

## §6. 신청 · 취소 플로우 (원§9, 원§10)

### §6-1. 신청
```
[신청] 클릭
   ↓
(CAPTCHA 모달 매회 — `VITE_CAPTCHA=on` 일 때 부록 A 그대로 발동, 기본 off: **D34**)
   ↓
서버 검증  ── 통과 → alert(성공) → 신청내역 테이블에 행 추가(순번 부여)
           └─ 실패 → alert(에러). 신청내역 변화 없음.
```
- **신청 후 조회 목록은 갱신되지 않는다** — 해당 행이 여전히 `신청` 파란 버튼 유지(원§10.3, 원본 UX 결함 — D4 / Q-3).

### §6-2. 취소 (신청내역에서만)
```
[취소] 클릭 → confirm(취소 확인) ── 확인 → 취소 요청 → alert(취소 완료) → 행 제거
                                 └─ 취소(cancel) → 아무 동작 없음
```

### §6-3. 마감
- `마감`(btn_grey2) 은 **비활성 처리가 아니라 애초에 핸들러 대상이 아니어서** 클릭되지 않는다(`href`·`onclick` 없음, 클래스 기준 이벤트 위임). 커서 포인터 없음.

### §6-4. 검증 우선순위 (원§10.1, 관측 기반) — 백엔드 검증, 프론트는 결과 메시지 표시
```
1. CAPTCHA 통과          실패 시 요청 보류, 재시도        (모의: VITE_CAPTCHA=on 시 D34 게이트, 기본 off)
2. 시간표 중복 검사       Duplicated time table
3. 동일 과목명 검사       Duplicated Subject
4. 학점 상한 검사         (미관측 — 자체 정의 메시지 §6-5)
5. 정원 검사             마감 버튼으로 사전 차단
```
- **2 와 3 은 독립적**: 시간이 겹치지 않아도 교과목명이 같으면 차단. (검증 사례: `게임프로그래밍` IAA6066001(화 2 3, 목 5 6) 신청 후 IAA6066002(수 5 6, 목 7 8) 시도 → 시간 미겹침에도 `Duplicated Subject`)
> 🙋🏻 **Q-14** 학점 상한 실제 값 미확보(학사요람 참조 필요) — 백엔드 설정값. 프론트는 메시지만 표시.

### §6-5. 메시지 전문 (원§9.2 사실 / 원§9.3 명세 자체 제안 → D6)
전부 **브라우저 네이티브 `alert()` / `confirm()`**. 포맷: `한글 문장` + `\n` + **공백 1칸** + `영문`.

|---|---|---|---|---|

## 부록 A. CAPTCHA 모달 원문 (D34: `VITE_CAPTCHA=on` 시 이 문구·동작 그대로 구현, 원§9.1)
```yaml
title: 수강신청 매크로 방지
trigger: 신청 버튼 클릭 시 매회
image: 4자리 숫자 + 노이즈 배경 (배경색 랜덤: 주황/노랑 관측)
body:
  - "1. 이미지에 보이는 숫자 4글자를 입력하고 \"확인\" 버튼을 클릭하세요."
  - "   Enter the four-digits number(string) that appears in the image and click the \"Confirm\" button."
  - "2. 오류 누적 횟수가 10회가 되면 자동 로그아웃 됩니다."
  - "   (문자열 오류 총 10회 중 N회 남음)"
  - "   If the string is still incorrect more than 10 times, you will be log out automatically."
  - "   (Total : 10  Remain : N)"
  - "3. 입력한 문자열이 맞을 경우 이전 요청이 자동 수행됩니다."
input_label: "※ 문자열 입력 :"
confirm_button: "확인(Confirm)"
close_button: "닫기"
error: |
  문자열을 잘 못 입력하였습니다. 다시 입력하세요.
  You entered the wrong string. Try again...
style: 흰 배경 + 파란 테두리 내부 박스 (jquery-confirm)
```
동작 관측: 이미지는 매 시도마다 재생성 · 오답 시 모달 유지 + 에러 문구 하단 추가 · Remain 10 → 8 관측(표본 부족) · 10회 소진 시 자동 로그아웃.

**구현 규칙(D34)**: 신청 버튼 클릭 시마다 발동 → 정답이면 보류된 신청 요청 자동 수행 → 오답이면 모달 유지 + 하단 파란 굵은 글씨 에러 문구 + 이미지 재생성 → 오류 누적 10회(오답 1회당 1 차감 — 하네스 기본, 표본 부족) 시 자동 로그아웃(`session.logout` → `/`). `닫기` 는 보류 요청 폐기. `VITE_CAPTCHA=off`(기본)면 게이트 없이 즉시 신청. 신청 플로우의 `beforeSubmit` 훅(`useCaptchaGate`)으로 구조화.
