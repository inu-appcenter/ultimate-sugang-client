# 규칙 — 확정 결정(Locked Decisions)

> spec 간 충돌·미확정 사항에 대해 **이미 내려진 결정**. 재논의 금지(바꾸려면 사용자 승인). 근거 spec 섹션 또는 사용자 결정 날짜를 함께 적는다.
> **harness-init** 이 초기 결정(기본값 채택 내역)을 D1~ 로 기록하고, 이후 빌드 중 사용자 결정이 나올 때마다 오케스트레이터가 이어서 추가한다.

## 작성 형식 (항목당)
```
## D{n} — {한 줄 제목}
- 결정 내용(무엇이 확정인지, 무엇이 금지인지).
- 적용 화면/영역.
- 근거: spec §번호 또는 "사용자 결정 YYYY-MM-DD".
```

## D1 — 백엔드 계약 미제공 → 어댑터 인터페이스 + mock 어댑터 기본

- 적용: 전 화면. 근거: 원§0 "서버·API 별도 존재" + 원부록 "엔드포인트 미조사" · 03 §2 N-1 · Q-1(승인 대상).

## D2 — shadcn/ui·sonner 미도입, 원본 CSS 이식 + 시맨틱 HTML + 네이티브 다이얼로그
- 원§6 CSS 를 `globals.css` 에 토큰 var() 로 치환 이식(`04 §4`), 컴포넌트는 원본 클래스명 사용. `<table>`·네이티브 `<select>`·`<button>`. `window.alert`/`confirm` 만(토스트·커스텀 모달 금지). `<font>` → `span.th-en`/`span.tag`. `#login`·`#noti_pop` id 선택자는 원문 유지(아키텍처 규칙 예외).
- 적용: 전 화면. 근거: 원§0 재현 대상(DOM·CSS) · 원§9.2 주석 · 03 §2 N-2. `rules/ui-conventions.md` "shadcn 우선" 은 이 프로젝트에서 이 결정으로 대체.
